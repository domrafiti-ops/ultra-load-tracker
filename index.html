How to read these

A strong positive correlation for Ê vs soreness means the eccentric channel is tracking your actual tissue response. A weak one points at km or your descent step length, not at the descent metres — those are measured, the other two are assumed. Adjust one at a time below and watch the correlation move; because nothing derived is stored, the entire history re-prices instantly.

If the Access Key is being rejected

      
A newly created Access Key has no permissions at all until you grant them — creating the key is not the same as enabling it. In JSONBin go to API Keys, open your key, and tick both Bins Read and Bins Update. The tracker needs both: Read to load the log, Update to save it.

      
Read and write are separate permissions. With only Bins Read, loading the log works and every save fails — so any test that checks only the read can pass while the app still cannot sync. Press Test connection: it probes both and names which one failed.

      
If Bins Update is genuinely granted and writes are still refused, the cause is probably not the key. The app sends X-Bin-Versioning on writes, and a custom header on a PUT has to survive a CORS preflight; if it does not, the browser blocks the request before it leaves — which looks exactly like a rejected key. The app now retries once without that header automatically and tells you if that is what fixed it. The sync doctor shows the raw HTTP status and JSONBin's own wording for every call.

What the Access Key protects, and what it does not

      
This is a static site, so the key you paste lives in your browser's local storage and is visible to anyone with your browser or devtools. That is why it must be an Access Key scoped to Bins Read + Bins Update — never your Master Key, which can create and delete every bin on your account. Someone who extracted this key could read or overwrite this one training log. For a personal training log that is an acceptable trade; do not put anything else in the bin.
